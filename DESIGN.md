# DESIGN — Bulls and Cows

Вся игровая логика лежит в `src/core/` и состоит из чистых функций без классов и без обращения к DOM.
`src/ui/` — тонкий слой, который собирает DOM через `createElement` и вызывает функции ядра.

## 1. Структуры данных и алгоритмы

### Структуры данных

| Структура                         | Где                                         | Почему                                                                                                                                                       |
| --------------------------------- | ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Секрет и попытка — `string`       | `types.ts`, `secret.ts`                     | Строка сохраняет лидирующие нули (`'0123'`), её удобно сравнивать и разбивать на символы (`[...s]`). Число в `number` потеряло бы ноль в начале.             |
| `GameState` — неизменяемый объект | `types.ts`, `state.ts`                      | Все поля `readonly`. Любое действие возвращает **новый** объект (`{ ...state, ... }`), старый не трогается — состояние легко тестировать и сравнивать.       |
| `history: readonly Attempt[]`     | `state.ts` → `submitGuess`                  | Массив, потому что важен порядок попыток. Добавление — `[...history, attempt]` (O(n), но n — число попыток игрока, это единицы-десятки), без `push`.         |
| `Set<string>` для цифр            | `digits.ts`, `evaluate.ts`, `validation.ts` | Проверка «есть ли символ среди допустимых/в секрете» и «нет ли повторов» за O(1) на символ.                                                                  |
| `Map<string, R>` как кэш          | `memoize.ts`                                | Единственная изменяемая структура ядра. Она спрятана внутри замыкания `memoize` и снаружи не видна: функция остаётся чистой с точки зрения вызывающего кода. |
| `GameRecord[]` в `localStorage`   | `records.ts`, `ui/storage.ts`               | Один общий массив; в каждой записи есть `length` и `base`, топ-N считается **отдельно на каждую комбинацию** length/base. Бейдж «4 · dec» виден в таблице.   |

### `evaluateGuess(secret, guess)`

Цифры в секрете уникальны, и в попытке тоже (проверяет `isValidGuess`). Поэтому:

1. `bulls` = количество позиций `i`, где `guess[i] === secret[i]` — `guessChars.filter((c, i) => c === secretChars[i]).length`.
2. `common` = количество цифр попытки, которые вообще есть в секрете — `filter(c => secretSet.has(c))`.
3. `cows` = `common − bulls` (общие цифры, которые не оказались быками).

Оба прохода сделаны через `filter`, без ручных циклов и счётчиков. Регистр приводится к нижнему (`toLowerCase`), поэтому `A` и `a` — одна цифра.

### `countPossibleSecrets(length, base)`

Количество секретов — число размещений без повторений: `P(base, length) = base! / (base − length)!`.
Ограничений на первую цифру нет, поэтому ноль в начале не вычитается.
Рекурсивное определение: `P(0, b) = 1`, `P(l, b) = b · P(l − 1, b − 1)`; при `l > b` результат `0`.
Функция обёрнута в `memoize` (кэш по `JSON.stringify(args)`), а рекурсивный вызов идёт через **мемоизированную** версию, поэтому промежуточные значения (`P(3, 9)`, `P(2, 8)`…) тоже переиспользуются.

### `generateSecret(length, base, random = Math.random)`

Рекурсивный выбор без возвращения: берём индекс `floor(random() * pool.length)`, забираем цифру, строим новый пул без неё (`filter`) и повторяем для `length − 1`. Источник случайности — параметр, поэтому в тестах `random` детерминирован. `Math.min(size − 1, …)` защищает от `random() === 1`.

## 2. Сложность (Big O)

Пусть `L` — длина секрета (2–6), `B` — основание системы (2–16), `L ≤ B`.

| Функция                | Сложность                                       | Обоснование                                                                                                                                                                                           |
| ---------------------- | ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `generateSecret`       | **O(L · B)**                                    | Рекурсия глубиной `L`; на каждом уровне `filter` пула — O(B), плюс сборка массива spread — O(L). Итого O(L·(B + L)) = O(L·B), так как `L ≤ B`. Память O(B).                                           |
| `evaluateGuess`        | **O(L)**                                        | Разбиение строк — O(L), построение `Set` секрета — O(L), два `filter` — по O(L) (проверка `Set.has` — O(1)). Без `Set` было бы O(L²).                                                                 |
| `isValidGuess`         | **O(L + B)**                                    | `createDigitValidator(base)` строит `Set` допустимых цифр один раз — O(B); `every` проверяет `L` символов по O(1); `new Set(chars)` для поиска повторов — O(L). Так как `B ≤ 16`, на практике O(L).   |
| `countPossibleSecrets` | **O(L)** на первый вызов, **O(1)** на повторные | Рекурсия делает `L` шагов, каждый — O(1) арифметика. Результат кэшируется (Map по ключу), повторный вызов с теми же аргументами — одно обращение к кэшу. Открытие настроек не пересчитывает значение. |

## 3. Принципы чистого кода

- **Чистые функции и отсутствие побочных эффектов** — всё в `src/core/`. Функции не читают DOM, `Date`, `Math.random` и т.д. напрямую: время передаётся как `now` (`state.ts` → `startGame`, `submitGuess`), случайность — как `random` (`secret.ts` → `generateSecret`).
- **Единственная ответственность (SRP) и маленькие функции** — каждая функция делает одно: `evaluate.ts` только считает bulls/cows, `validation.ts` только проверяет ввод, `records.ts` только управляет рекордами. Файлы названы по предметной области.
- **DRY** — `createDigitValidator` (`digits.ts`) используется в `validation.ts` → `isValidGuess` и в `ui/main.ts` → фильтрация ввода; одна проверка «допустимая цифра» на всё приложение. Единый `memoize.ts` вместо ручных кэшей.
- **Говорящие имена** — `availableLengths`, `isRepeat`, `checkGuess`, `recordFromState`, `elapsedMs`; булевы функции начинаются с `is`/`has`/`check`.
- **Никаких магических чисел** — `LENGTHS`, `BASES`, `BASE_NAMES` (`state.ts`), `RECORDS_LIMIT` (`records.ts`), `ALPHABET` (`digits.ts`).
- **Ранние возвраты (guard clauses)** — `checkGuess` и `submitGuess` (`state.ts`), `generateSecret` (проверка границ с `RangeError`), вместо глубокой вложенности.
- **Иммутабельность** — `readonly`-типы в `types.ts`; обновления через spread (`{ ...state }`, `[...history, attempt]`). ESLint запрещает классы (`no-restricted-syntax`), `innerHTML` и `insertAdjacentHTML` (`eslint.config.js`).
- **Разделение слоёв** — `core` не импортирует `ui`; побочные эффекты (DOM, `localStorage`, таймер) собраны в `src/ui/`. `ui/storage.ts` изолирует `localStorage`, а разбор JSON (`parseRecords`) — чистая функция в ядре и тестируется без браузера.
- **Безопасная обработка ошибок** — `parseRecords` не падает на битых данных, `storage.ts` ловит исключения `localStorage`.
- **Тесты как документация (TDD, FIRST)** — тесты лежат рядом с кодом (`*.test.ts`), быстрые, независимые, детерминированные (`seeded`, `sequence` в `secret.test.ts`) и самопроверяющиеся.
